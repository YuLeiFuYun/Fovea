# Workbench 视觉与交互保证

## 1. 问题边界

Workbench 曾把“页面能打开、Accessibility 元素存在、按钮能被点击”当成 UI 验收。该标准无法发现以下用户可见缺陷：

- 内容图片实际仍是纯色测试块或长期占位；
- `.fill` 图片被外层 `.fit` 约束，导致留白、错误裁切或容器未填满；
- 图片、文字和浮层越界或互相遮挡；
- 按钮过窄、过宽、文字被压缩或触控区域不足；
- 中文界面混入不必要的英文；
- 点击操作没有产生可观察的状态、图片或证据变化；
- iPhone 上可用的布局在 iPad、横屏或动态文字下失效。

视觉质量不是一个能由单一像素 diff 完全证明的性质。本项目采用多种相互独立的有限 oracle，降低共同盲区。

## 2. 每个视觉检查点保存的证据

`FoveaWorkbenchVisualTests` 对 iPhone 和 iPad 的代表性页面保存：

1. `XCUIScreen` 原始 PNG；
2. 完整 Accessibility 树；
3. 可见按钮、图片和文字的 frame JSON；
4. 小于 44×44 pt 的按钮；
5. 水平方向逃逸出 window 且未声明为横向轨道项目的元素；纵向滚动内容和有稳定轨道身份的横向滚动项目不自动判为越界；
6. 重叠面积超过较小图片 25% 的可疑图片组合。

当前矩阵覆盖：

- 生态图谱首页；
- 验证中心；
- 证据与运行；
- 设置；
- 代表性生态专题；
- 场景工坊竖屏；
- 场景工坊横屏。

后续新增一级页面时必须同步扩展矩阵。

## 3. 独立审查器

`scripts/audit-workbench-visuals.py` 不依赖应用内部状态，执行以下检查：

- 内容资源可解码、尺寸足够、不是已知纯色 fixture；
- 用户可见 SwiftUI 直接文案中的未解释英文；
- `.fill` 与外层 `.fit` 的冲突组合；
- 通过 `minimumScaleFactor` 掩盖按钮布局问题；
- `overlay + offset` 的高风险越界组合；
- 截图的颜色多样性、通道方差和均匀 tile 比例；
- 几何附件中的小按钮、未声明的水平越界和高比例图片重叠；纵向滚动内容及已声明横向轨道项目必须结合滚动容器与截图人工复核。

审查器包含合成变异自测，必须识别：纯色内容图、75% 覆盖容器、32 pt 按钮、大面积图片重叠和未声明的水平逃逸；同时不得拒绝高变化图片、48 pt 按钮、完整覆盖、小装饰交叠、正常位于首屏下方的纵向滚动内容，或以稳定 `ecology.featured.*` 身份声明的横向轨道项目及其同框子图。

## 4. 模式

- `baseline`：记录现状缺陷并返回零，用于重写前基线；报告中的 `status` 仍为 `failed`。
- `assets`：严格检查真实内容素材。
- `localization`：严格检查直接用户文案。
- `primary`：检查素材、中文、关键布局与现有截图。
- `verify`：最终严格门。

示例：

```sh
FOVEA_IPHONE_SIMULATOR_ID=<UDID> \
FOVEA_IPAD_SIMULATOR_ID=<UDID> \
python3 scripts/audit-workbench-visuals.py --mode baseline --capture
```

产物位于 `.artifacts/ios-example/visual-audit/`，包括两个 `.xcresult`、导出的附件、构建日志和 JSON 报告。

## 5. 图片语义

内容图片、加载占位和错误态必须明确区分：

- 内容图片必须是有来源的真实摄影或插画；
- 自动化可使用本地真实 fixture，但不得用纯色块冒充内容；
- 骨架只在请求尚未完成时显示，并与最终容器同尺寸；
- 失败态必须明确说明失败，不得看起来像正常图片；
- `.fit` 用于需要完整保留图像边界的检查页面；
- `.fill` 用于头像、Hero、卡片缩略图等固定容器，并必须 clipping。

容器比例、图片模式和 clipping 只能由一个共享图片表面组件拥有，禁止调用方叠加相互冲突的第二层比例策略。

## 6. 交互 oracle

按钮测试至少验证一个点击前后变化：

- 状态或 accessibility value 改变；
- 图片 revision 或可见内容改变；
- 缓存、源站、共享任务或诊断计数改变；
- 运行记录新增；
- 明确失败分类出现。

只断言按钮存在、可点击或页面未崩溃，不构成功能验证。

视觉截图、几何树和控件可点击性即使全部通过，也不能证明异步业务动作已经完成。行为测试必须等待产品实际发布的稳定状态身份，并断言该身份当前公开的本地化 accessibility label 或 value；不得继续匹配已经从产品语义中移除的旧语言片段。若 XCTest、SpringBoard 或 Simulator 的 Accessibility 服务返回超时、无效激活点或 `kAXErrorServerNotFound`，验证器必须把它记录为基础设施失败并有界重试，不能把缺失的状态刷新解释为产品成功。

## 7. 人工审查

自动检查无法证明美观、信息层级合理或图片选材恰当。最终候选必须查看导出的完整截图矩阵，逐项确认：

- 图片选用正确；
- 主次层级清楚；
- 文案自然且全中文；
- 不存在裁切错误、留白、遮挡和跳动；
- 按钮尺寸、位置和分组符合任务语义；
- iPhone/iPad、横竖屏均可读。

人工审查不能替代几何和状态断言；两者必须同时通过。

## 报告稳定性

审查报告使用完整的 `code + severity + path + detail` 作为缺陷身份并进行稳定去重，
避免同一 SwiftUI 控件因 Accessibility 暴露多个等价节点而被重复计数。报告发布
`oracleVersion`；`1.1.0` 将纵向首屏外内容从“越界”中排除，`1.2.0` 又把稳定声明的横向轨道项目及其同框子图从水平逃逸中排除。任何阈值、过滤规则或缺陷身份变化都必须提升该版本并保留旧基线。

报告同时声明固定采集矩阵：`iphone` 与 `ipad` 两个设备族，每个设备族七个检查点。
矩阵数量变化属于视觉合同变化，必须同步测试、文档和报告版本。

## 独立 oracle 自检

`python3 scripts/audit-workbench-visuals.py --self-test-only` 只运行十二项缺陷变异控制，
不读取 Simulator、不构建应用，也不复用页面截图。该入口用于证明审查器仍能识别纯色
内容图、大面积重叠、过小按钮和未覆盖容器，同时不会误伤高变化图片、合法按钮、
完整覆盖、小装饰叠层、纵向滚动内容和已声明的横向轨道项目。

每份完整报告还包含 `findingFingerprint`：它对去重后的完整缺陷记录进行稳定 SHA-256
摘要。同一代码树、附件矩阵和 oracle 版本应得到相同指纹；指纹变化必须归因于代码、
附件或 oracle 版本变化。
